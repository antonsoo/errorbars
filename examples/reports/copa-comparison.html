Read this comparison with its assumptions

  • Pairing uses question ids and rejects conflicting known question signatures. Missing signatures leave content identity unchecked. Matching signatures are not a check on scoring rules: confirm comparable metrics and filters. Prompt variants may intentionally differ.
  • Intervals describe sampling uncertainty under the chosen question/cluster model. An interval containing zero does not establish equivalence. No multiple-comparison adjustment is applied to this single comparison.

Record numbers are one-based, excluding CSV headers. Line ranges are physical file lines; CSV ranges may include blank separators. Inspect logs use record order, sample id and epoch.

This file includes model, question and cluster identifiers, scores, sample labels and source filenames. It does not include raw prompts, completions or full source paths. Files with the same name have distinct source numbers. A source location identifies an imported record; it is not a content checksum.

Native lm-eval imports fingerprint the logged document and target using a versioned SHA-256 signature. Prompts and responses do not enter that signature. Canonical inputs may provide a question_hash column. A missing signature is unchecked; a partial check means some repeated observations lack a signature. Conflicting signatures block inference across the whole cohort and remain in the ledger.

JSON retains every question and observation, including rows not currently shown. CSV contains all questions matching the current filters, across all pages. Text cells beginning with spreadsheet formula characters are prefixed with an apostrophe in CSV; JSON preserves original identifiers.

Display precision is limited; exports retain the stored numeric values. No data is sent over the network.
