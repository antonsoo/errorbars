# Binary power-planning feasibility verification

The repaired planner checks that a proposed baseline, improved accuracy and
pairing correlation can describe a joint binary distribution. Baseline source
`6adea05815b239b5dd945b104e92f3033a3167e7` returned **2 questions** for
baseline .8, improvement .05 and correlation 1, and **57 questions** for
baseline .9, improvement .05 and correlation .9. Both comparisons are impossible.
The corresponding fixed-budget perfect-correlation case returned MDE 0.
All three now produce an actionable error and cannot be exported by the browser.

The implementation is in
[`77ca760`](https://github.com/antonsoo/errorbars/commit/77ca7602b383e202497c655497cfb5683b1ccc21).
The [study](../studies/binary-feasibility/README.md) retains scripts, full CLI
output, downloaded plans, screenshots and independent numerical checks.

## Behavior checked

| Scenario | Result |
| --- | --- |
| Impossible positive-correlation target | Error names the permitted gap range; stale output hidden and download disabled |
| Baseline .2, correlation -.5, budget 1,000 | 30-point minimum possible improvement, with a correlation-limit explanation and flat curve |
| Baseline .9, correlation .5, budget 135 | Valid 7.234-point plan remains visible; correlation-zero sensitivity and the smaller comparison budget are unavailable |
| Correcting an invalid active input | Result and download recover with the corrected assumptions |
| Default plan | Still 3,053 questions per model at correlation .3; 4,361 at correlation 0 |
| Continuous scores / repeated averages | Existing variance model retained; feasibility metadata is null |

The negative-correlation example previously returned a 6.138-point gap even
though every possible paired binary outcome under those assumptions requires
at least a 30-point improvement. This lower bound cannot be reduced by asking
more questions. It is separate from the statistical detection threshold.

## Independent mathematical evidence

The study evaluates the four joint probabilities at 70-digit precision from
the exact float inputs. It does not use the production interval equations as
its classification oracle. All **6,776** integer 2x2 tables with totals 5, 10,
20 and 40, interior marginals and positive improvement have accepted forward
plans and feasible inverse results within floating-point tolerance.

The separate **1,781-case** parameter grid has no material classification
disagreement. Five floating-point boundary differences are recorded, including
two targets whose float sums round to 100% accuracy and therefore have no
representable target variance. The smallest returned joint cell in the table
study is about `-6.92e-17`. The production interval uses a relative roundoff
tolerance at closed endpoints; it does not claim exact real arithmetic.

**15,238** Python/TypeScript calls agree in the source and both installed-wheel
studies. Ninety-five tiny-effect grid cases exceed the representable question
count range and are excluded from numeric budget parity, while their feasibility
is checked separately. The old 600 shared fixtures retain all inputs, including
51 forward and 46 inverse cases now marked unavailable. See
[oracle.json](../studies/binary-feasibility/results/oracle.json),
[Python 3.10](../studies/binary-feasibility/results/oracle310.json), and
[Python 3.14](../studies/binary-feasibility/results/oracle314.json).

## Limits and publication boundary

This is a feasibility repair to the existing common-baseline-variance normal
approximation, not exact McNemar power or proof of achieved power. Large gaps,
small samples, uncertain correlations, unequal groups and few independent
groups still require further design checks. Continuous and repeated-answer
joint distributions are not validated. The selected scenarios and enumerated
tables are controlled mathematical cases, not new model evaluations.

Only source publication is intended here. No release tag, package release or
hosted-site deployment is part of this change. The web build command is
`npm --prefix web run build`; its output is `web/dist`.
