## What changed

The previous `power` command divided the entire single-answer variance by the
repeat count. A baseline of 0.5, target difference 0.05, and 100 answers per
question produced a 16-question budget, regardless of whether answers on
the same question were correlated. The repaired CLI and Python/TypeScript
APIs require an explicit repeat assumption and use the persistent variance
component. The [guide](repeated-planning.md) documents migration and limits.

No new showcase or interface was needed. The existing browser calculator
still plans one answer per question. Repeated-answer workflows use the CLI
or the formula APIs.

## Remaining limits and repository metadata

This fixes one planning assumption. Equal marginal variances, target-repeat
pairing correlation, representative question sampling, normal-approximation
power and any passage-level design effect remain assumptions. Multiple
comparisons, adaptive sampling, pass@k and voting need other designs. The
new explicit parameter is a deliberate compatibility change for repeated
plans; existing scripts must choose their assumption.

Suggested repository description (no metadata was changed):
"Error bars and defensible budgets for LLM evaluations, with paired comparisons and question-level evidence."

Suggested topics: `llm-evaluation`, `statistics`, `power-analysis`,
`confidence-intervals`, `benchmarking`, `python`.
